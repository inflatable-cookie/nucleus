# Longhorn Settings Shell Implementation

Date: 2026-08-02
Status: complete
Roadmap: g05.010
Cards: 030-032

## Outcome

Nucleus now has one sparse Settings dialog over Longhorn's registry, session,
config, and public Poodle composition. Nucleus owns the two initial page
schemas and effects:

- General applies the fixture-status indicator immediately
- Appearance stages compact or comfortable interface density

Both project one durable Nucleus preferences domain. The host seals one
generation with typed scope and apply-unit authority. Failed publication,
stale generation, stale authority, cross-domain commands, duplicate
registration, reset, restart, and caller authorization fail or recover through
the checked host path.

The renderer mounts one isolated modal session from the titlebar. General and
Appearance are separate lazy chunks. Search, close guards, conflict display,
remount, reset, staged Apply, and immediate writes use Longhorn session
semantics and public Poodle controls. Native Browser content is hidden while
the modal intersects it and restored after close.

## Native Findings

Native acceptance found two integration defects that deterministic component
fixtures did not expose.

First, Longhorn's stock Tauri commands require the caller to be a
`WebviewWindow`. Nucleus may attach Browser child webviews to the primary
window, so its main caller cannot always be represented by that single-webview
type. The Nucleus adapter now accepts a generic caller webview, derives the
parent window label for authorization, and retains Longhorn's command service
and mutation semantics.

Second, General and Appearance share one config authority revision. Applying
one scope made the other scope's cached authority stale. Nucleus now publishes
invalidation hints for every sibling scope sharing that domain. The focused
fixture proves both scope ids are projected from each successful mutation.

The native modal, page navigation, immediate apply, staged apply, dirty close
guard, remount, persisted value projection, and Browser suppression passed.
The rebuilt app then passed the final Appearance apply -> General immediate
write -> General reset -> Appearance reset sequence without a false stale
conflict. Restart restored compact density and enabled fixture status.
