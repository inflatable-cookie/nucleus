## Objective

Register semantic Nucleus commands and route each invocation through fresh
product admission and typed execution.

## Acceptance

- [x] shell, project, thread, panel, editor, Forge, and turn actions are inventoried
- [x] every command has stable identity, context, availability, and typed execution
- [x] invocation reruns current authorization and state admission
- [x] command ids do not become Tauri invoke or server command ids

## Validation

- [x] catalogue, context, stale-state, and authorization fixtures pass

## Stop Conditions

- do not replace component-local editing or accessibility behavior with global commands

## Evidence

- one sealed generation registers 26 semantic commands across shell, project,
  thread, panel, editor, Forge, and Agent Chat turn domains
- rooted contexts, explicit capabilities, and coded product-state availability
  are projected from one Nucleus state snapshot per projection or invocation
- every invocation reruns Longhorn admission before resolving one opaque route
  into the typed Nucleus executor port
- command ids and product route ids are distinct; neither becomes a Tauri
  invoke name, control-envelope id, or server command id
- the foundation stays host-local until cards 037-038 add keymap persistence
  and renderer presentation; no generic command-to-Tauri executor was added
- focused fixtures pass stale registry, unknown command, invalid arguments,
  missing capability, stale availability, typed route, and authorization cases
