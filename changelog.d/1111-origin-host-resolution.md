Origin host resolution over several hosts. A host now answers an origin lookup one of
three ways — the thread is mine, the host authoritatively has no such thread, or the
read proved nothing — and only one claimant with every other host ruled out resolves
the origin. The T3Code adapter reads the complete inventory before it reads a
projection, so a thread T3 does not have is absence instead of an error, and a
failed or incomplete read stays unknown. An offline registered host no longer blocks
resolution when the thread's own identity source already proved its host: the caller
resolution (`caller.resolve`, a run ticket or a Paseo identity) travels with the
commands that name that same thread, so `lead.submit`, a handoff, a promotion and
`question.answer` resolve while another host is offline. Two claimants still refuse.

A promotion refused before any insert now settles as refused before commit, so a retry
promotes the same lead exactly once instead of leaving an uncertain effect in
attention, and reconciliation settles such an operation once its own process is no
longer executing it. A settled promotion's reply names the host selection its task
took, which follows the repository's `hostKind` at promotion time.

Planner participant tickets no longer revive threads. Startup reconciles and sends
nothing; the ticket reaches a planner in the response to its own next authenticated
call, or in the response to the assignment that named it. A message is the last route
— one message, only to a thread observed live on a host with no calling-thread
identity of its own — and an archived, gone or unreadable thread is left ticket
pending, shown on the board's project entry.
