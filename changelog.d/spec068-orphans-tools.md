### Changed

- A task left in `working`, `changes_requested`, `awaiting_review` or `reviewing` with no live run, stop or hold now returns to its worker or reviewer on its own after five minutes, through `move to=work` or `move to=review` (Spec 068). A revision that reported and was released without its result being applied now goes through the normal result handling, so a pushed head goes to review and a blocked report goes through the usual blocker handling. When Nucleus can't readmit a task, or has already tried three times, it records a stop that names the cause and the command to run.
- A finished revision whose worker's thread is still busy now shows that it is waiting for the thread, instead of sitting in `changes_requested` with no explanation.
- A worker's or reviewer's shell command that has shown output and then printed nothing for 30 minutes is now stopped, and the agent carries on after a failed tool call. Nucleus finds the command's own processes by process ID and start time and never touches the agent's turn. A command that hasn't shown any output yet is left alone. A repository can change the limit with `toolQuietLimitMinutes` in `repository.set`.
- A tool call stopped together with its turn (T3's "Stopped by user") no longer keeps the run held, unless a process it started is still running.
- A permission prompt in a worker, revision or reviewer run is now declined automatically, and the agent is told to carry on without that permission or report it as a blocker. The task history records each prompt that was declined. If Nucleus can't tell whether a decline reached the host, it doesn't send it again, and the prompt is reported as a stalled turn. Paseo can now answer permission requests too.
