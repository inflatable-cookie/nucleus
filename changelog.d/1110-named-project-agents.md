A project can now register named, non-task threads — planners, leads and cross-section coordinators — and other threads address them by name. `agent.register` records a thread with its purpose and host and delivers its participant ticket; `agent.unregister` removes it; `project.agents` lists each entry's host, live state, last seen and fallback marker, and Settings → Projects shows the same list. Names are unique per project and a thread holds one name, so renaming or reassigning a name revokes the old ticket. `project.set-planner` now marks a registered agent as the project's fallback planner — the thread `to: {project}` resolves to — and registers an unregistered thread under the default name `planner`. Naming an agent resolves at send time; an archived or gone thread fails with that state and a pointer to `project.agents`, and Nucleus sends nothing, so naming can never revive an archived thread.
