Quitting Paseo no longer puts a global failure banner on a healthy board or stalls T3 work. Connection and bootstrap readiness now belong to the verified host that owns the work: while T3Code is online, the primary Paseo adapter's connect is retried within its existing bound as that host's own recovery, and its failure is shown as that host being offline with its cause instead of as a runtime start error. Durable operation recovery, bulk-disposition resume, the first reconciliation and the catalog pass run once with T3 as the only online host, on a cold start and when an already running T3 host loses Paseo; the catalog pass reads each online host's own catalog and skips an offline adapter, and Paseo-bound tasks keep waiting on Paseo. A genuine start, store or engine fault still shows on the board, and a lost primary never loses the primary's claim on its own tasks.
