The BB board now loads Plans through the dotted `queue.plans` RPC and can read host-run QA data through its bridge. BB threads can use their verified `BB_THREAD_ID` as the CLI caller for planning commands and submission ingress; promoted tasks keep the repository or operator-default work host. An offline selected BB ingress host now returns a named `invalid_input` refusal before accepting work. The board's bridge also serves the typed service-state read. BB run launches create the recorded owner-only scratch directory first and use the repository's configured scratch namespace.
