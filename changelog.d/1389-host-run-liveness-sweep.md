The host-run sweep now proves every admission reservation's recorded process on its own evidence, so a run whose hook process is gone settles on the next pass instead of holding its task's workspace and its heavy slot until its 24-hour timeout. A dead pid settles as abandoned with the outcome left unknown; a reused pid number settles the same way; a live process carrying the recorded start identity keeps its slot; and an unreadable process table holds and records `hook_liveness_unknown` on the run so the hold has a visible cause.
