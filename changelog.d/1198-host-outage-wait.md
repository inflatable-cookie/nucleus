A task whose host is unavailable now waits visibly on that host: its stop reads `host_unavailable` with the host named and the time it went offline, nothing is sent to the host, no recovery or escalation is raised from the outage, and the wall-time budget pauses. New dispatch for a project on that host waits the same way. When the host returns, the retained threads are re-observed before anything is sent and the task continues on the same host and threads. Past a new dispatch-limits bound (`hostOutageNoticeMinutes`, two hours by default) each affected project's planner is told once per outage, naming the host, its start and the waiting tasks; the board card shows the same wait.
