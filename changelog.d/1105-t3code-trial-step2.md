T3Code trial step 2. Threads on a host without per-thread MCP report through
the packaged nucleus helper with the run ticket named in the prompt; a report
for another run is refused. Paseo keeps its MCP reporting route. Nucleus-raised
questions on a host that cannot take a native question land on the web board
and the project planner's agent channel; recovery sweeps keep that board route
and retry a missed planner notice instead of prompting the T3 worker to call
MCP. Helper asks wait longer than the server's bounded answer. The T3 workflow
adapter composes through the public `core/host` policy port, so review
verification and retained-thread continuation use the same Nucleus policy as
Paseo. Helper asks reach a retained T3 reviewer through `askReviewer`; the
consultation names the recipient run's helper ticket and the `answer`
subcommand, the same authenticated run-bound callback as reporting. A released
reviewer run is re-issued a consult ticket so `/answer` authenticates; complete
and ask keep refusing that run. T3-hosted planners are out of trial: when the
selected planner cannot be asked on its host, the ask becomes an answerable
board decision with the planner message, never a silently pending ask.
Uncertain reviewer or coordinator creation binds through `findRunAgents`. A
repository setting selects the host (`paseo` default, `t3code` opt-in); live
tasks keep the host they started on. Settings and `repository.set` switch the
project for new tasks.

Trial: start T3Code, issue a session bearer with `t3 auth session issue`, store
it owner-only in local settings as `t3code: {endpoint, bearer, probeThreadId?}`,
opt a project in via Settings → Host or `repository.set`, and switch back the
same way.
