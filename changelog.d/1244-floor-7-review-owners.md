The review phase's modules now have one owner per mechanism. The retained
reviewer's continuation is a folder: the checkpoint file and its proof, the
delivery identity and owner-stop proof, the retained reader's state and wait, the
earlier-result fence, and the gate's local refusal order, composed by the one
authorized reviewer turn. The review lifecycle keeps its behaviours in four
narrow owners — reviewer opt-in with the shared review requirement, continued PR
identity, the ordinary round's custody proof, and the transitions out of
reviewing. A PR the task knows only from a report is bound only from that
report's own authenticated receipt and only when the observed PR comes from the
canonical repository; a task with no PR and a foreign PR stay separate answers.
The ordinary reviewer reports a checkout identity failure by its typed cause
instead of the shape of the message, and the receipt-hash read the review and
retained-work modules repeated is one store read. `core/review/review-body.ts`
is gone; review publication imports the shared review text directly. No product
behaviour changes beyond those removals.
