BB presentation now follows a task's planner instead of refusing the dispatch. A task whose planner thread lives on this BB host nests under it as before; a task whose planner is on T3, Paseo or nowhere dispatches as a standalone top-level task group, and its questions still climb the task's real planner ladder on the planner's own host. A planner change re-nests the group, a planner elsewhere stands it alone, and the new `detach` owner verb (board, task row and `nucleus helper detach`) records that a task's presentation has no planner thread so a planner can be archived or replaced without taking its tasks' threads with it; naming a new planner clears the record. The BB sidebar stops saying "No threads" over a project whose task nests under another project's planner, showing one compact pointer row, "1 task under <planner title>", that opens the nested group. A task container now leads its state line with the folder icon and the repository label, draws its PR as the state icon plus `#39` in the state colour (the board badge's one shared mapping), and offers only the task's own actions — open the task, open the PR, detach from the planner — instead of upstream's new-thread, Edit and Archive. Thread titles name the full reference (`poodle-lab#29`), with the worker named by role once the container holds more than one participant. A superseded participant now leaves the container: a replaced reviewer, recovery or coordinator thread is archived once its own run is settled and no binding names it, while a live or pending-interaction thread, the planner and the task's other threads stay.
