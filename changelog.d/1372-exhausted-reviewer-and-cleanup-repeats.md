An exhausted retained reviewer no longer sits silently, and run cleanup stops
repeating one decision.

A reviewer that reports it cannot finish the remaining reading is ruled out at
that head. Once its own agent is observed settled, the ordinary sweep performs
the `restart role=reviewer fresh` the board already offered — the same exact-head
rule, under the same retirement ceiling as any fresh replacement — so the reader
is replaced on the pass that observes it instead of waiting for a person. Where
the replacement cannot act, or the ceiling is spent, the sweep opens the planner
escalation with that verb in the question and the refusal named on the wait. The
escalation belongs to the reader, so a replacement that later exhausts is its own
episode rather than a silent repeat of an answered one (nucleus#1358's reader sat
idle for five hours while `next` offered the verb and nothing acted).

Run cleanup also stops treating a shared provider host as a released run's live
ancestor. The provider's own `app-server` is started and kept by the host daemon
and inherits the launching thread's ticket and scratch in its environment, so it
still names that run after the run released; it is host infrastructure, and it no
longer holds the scratch or repeats a left-alone record. A genuinely owned live
process still holds, and still records once. A left-alone decision is now written
once and again only when it changes, and re-queueing the same cleanup obligation
(a release, a replacement or an idle observation of the run) no longer erases the
recorded decision — the shape that wrote 770 identical records for one archived
reviewer run in six hours.
