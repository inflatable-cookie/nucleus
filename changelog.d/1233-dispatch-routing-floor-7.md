Participant tickets, routing and the routing sign-off each have one owner. The three near-copy ticket issue/deliver routines (planner, task planner, named agent) are one `issueTicket` over a scope descriptor, with the meta keys, stored records and participant scopes built and read in one place, so no caller assembles a key or splits one to learn what a ticket speaks for. A failed ticket issuance in the caller's own call is recorded instead of returning an unexplained absence, and a project whose planner host cannot be proven registers no fallback agent on the service's own host. The routing sign-off and planner grants are one module, `core/dispatch/routing-signoff/`: the sign-off record's rules and the typed event decode live once, a withdrawal that did not happen is recorded, and a per-task pass no longer re-settles every live task, so a sweep is linear in tasks instead of quadratic. Routing reads the one model-key normalisation in `shared/authors.ts` and the store's typed availability rows, instead of carrying a second model key with different opaque rules and three raw availability queries.
